# Как требования работодателей переводятся в задания ПРОБЫ

**Исследовательский артефакт — 23.10.2026.** Это предложения для будущих симуляций, не подтверждение уже реализованных в продукте задач. Основание: [выборка 16 объявлений](../data/verified_entry_roles_2026-10-23.csv).

| Профессия | Типовая рабочая ситуация | Что должен сделать участник | Проверяемый артефакт | Проверка качества |
| --- | --- | --- | --- | --- |
| Системный аналитик | Заказчик просит добавить API-интеграцию | Уточнить требования, нарисовать поток и спецификацию методов | Требования + UML/BPMN + API-контракт | Непротиворечивость сценариев, наличие ошибок/пограничных случаев, трассировка требований |
| Менеджер проектов | Сроки релиза под угрозой из-за двух зависимых команд | Пересоставить план, согласовать риски и статусы, подготовить протокол встречи | План-график + risk log + статус-отчёт | Явные ответственные, даты, зависимости, эскалация |
| Финансовый аналитик | Нужно оценить расширение сети офисов | Построить модель потоков, ROI/NPV и сценарии чувствительности | Excel-модель + короткая инвестиционная записка | Воспроизводимые формулы, обоснованные допущения, соответствие выводов расчётам |
| Интернет-маркетолог | Рекламная кампания даёт много кликов, но мало лидов | Проанализировать CTR/CPL/CR и предложить A/B-тест | Таблица метрик + гипотезы + медиаплан | Арифметика, корректная постановка теста, отсутствие причинных выводов без эксперимента |
| Python-разработчик | Команде нужен регулярный отчёт из сырых событий | Реализовать функцию очистки и агрегации данных, обработать ошибки | Код Python + тесты + демонстрационный отчёт | Граничные случаи, читаемость, корректность подсчётов |
| Frontend-разработчик | Нужно связать новую форму с API | Собрать компонент Vue + TypeScript и проверить состояния загрузки/ошибки | Исходник компонента + e2e-тест | Валидация, доступность, обработка ошибок, прохождение тестов |
| Data Scientist | Есть изображения обращений, нужна автоматическая классификация | Провести EDA, разделить данные, оценить baseline и ошибки модели | Ноутбук + метрики + error analysis | Отсутствие data leakage, корректные train/test-разбиения, уместность метрик |

## Уровень подтверждения

- **Из объявлений:** профессии и типовые рабочие операции. Примеры: UML/API у системного аналитика, Excel/финансовые модели у финансового аналитика, Vue/TypeScript у frontend, Python/ML у Data Scientist.
- **Наш продуктовый дизайн (гипотеза):** конкретные кейсы, последовательность шагов, форматы артефактов, критерии проверки.
- **Не подтверждено:** что эти кейсы подходят по сложности для новичков, имеют высокую конверсию, или уже прошли независимую экспертизу специалиста.

## Операционные риски

Разработка заданий с помощью ИИ сокращает стоимость черновиков, **но не устраняет стоимость проверки**. Особое внимание нужно уделить двум рискам: (1) правдоподобность бизнес-кейса, (2) надёжность автоматической оценки сложных открытых ответов. Для финансовых задач и заданий по данным должны быть фиксированы данные, формулы и проверяемые ожидания.

## Следующий шаг

Собрать по каждому предложенному кейсу минимальный датасет и эталон, затем протестировать 3–5 разных решений (правильное, частично правильное, ошибочное) и зафиксировать результаты ручной/автоматической проверки. До этого сценарии нельзя считать готовыми профессиональными пробами.
