# Измерение интереса к профессиям в ПРОБЕ: проект аналитического эксперимента

**Статус:** схема будущего эксперимента, **не реализованный трекинг и не реальные измерения**. 23 октября 2026 г.

## Задача

Отличить **желание попробовать профессию** от объёма вакансий работодателей. Приоритизировать разработку новых проб нужно по данным потенциальных пользователей, а не по одному индексу стажировок.

## Гипотеза

Спрос на потенциальную пробу можно приблизительно оценить по фактическому выбору направления среди пользователей, которым одинаково видны все варианты. Наличие клика на карточку — лишь слабый сигнал, более сильные — запись в лист ожидания, начало пробы и завершение.

## Требования к эксперименту

1. Протестировать **одинаковую видимость** семи кандидатов, избегать позиции в каталоге как скрытого фактора. Менять порядок карточек случайно и сохранять информацию об экспозиции.
2. Для ещё не реализованных проб предложить прозрачную **кнопку «Хочу попробовать / Узнать о запуске»**, без ложного обещания доступности.
3. Не смешивать пользователей из разных стран без сегментирования и учёта разницы каналов привлечения.
4. Записывать технический анонимный идентификатор сессии, дату, профессию, вариант размещения и тип события. Не собирать в аналитику ФИО, email, тексты ответов или другие данные, не нужные для проверки гипотезы.
5. Перед продакшен-сбором проверить уведомления и правовые основания обработки данных, сроки хранения и механизм отказа, особенно если используется сквозная идентификация.
6. Проверить корректность event instrumentation тестовыми визитами и отсутствие дублей при перезагрузке страницы.

### Черновая схема событий

| Событие | Значение | Главная оговорка |
| --- | --- | --- |
| `card_impression` | Карточка оказалась видимой | Не означает интерес |
| `card_open` | Пользователь открыл описание | Возможен случайный клик |
| `waitlist_intent` | Явно запросил уведомление/желание попробовать | Относительно сильный сигнал, но не покупка |
| `trial_start` | Начало доступной пробы | Недоступно для ещё не выпущенных кандидатов |
| `trial_complete` | Завершение пробы | Зависит от сложности контента и времени |
| `purchase` | Реальная оплата | Транзакцию не путать с намерением купить |

**Схема события:** `event_id`, `anon_session_id`, `event_time`, `profession_id`, `experiment_variant`, `event_name`. Для конверсии по пользователям нужен отдельный контролируемый идентификатор с правовой проверкой; демо-SQL использует `anon_session_id` и поэтому считает **сессии**, не уникальных людей.

## Показатели

- `open_rate = уникальные сессии открытия / уникальные сессии показов`;
- `intent_rate = уникальные сессии выраженного интереса / уникальные сессии показов`;
- интервальные оценки (например, Wilson) и минимальные размеры выборок по каждому направлению;
- конверсию нельзя сравнивать при разных способах показа, источниках трафика и разных сроках наблюдения;
- основное решение желательно принимать по заранее выбранному первичному показателю, а не по лучшему из шести после анализа.

## Решение о запуске

Сопоставить интерес пользователей, очищенную доступность карьерного входа, проверяемость задач и стоимость контент-QA. Если профессия имеет высокий интерес, но очень мало стажировок, она может быть полезной профориентационной пробой, но нельзя обещать по ней высокие шансы трудоустройства.

**Что требуется для выполнения:** команда продукта добавляет анонимные события с проверкой legal/privacy, после чего проводится заранее описанный пилот. До этого собранные внешние данные остаются косвенными признаками.
