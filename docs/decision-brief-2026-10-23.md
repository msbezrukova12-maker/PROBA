# ПРОБА — решение о следующем пилоте профессиональных проб

**Дата:** 23.10.2026 · **Тип документа:** decision brief / продуктовая гипотеза, а не подтверждённый рейтинг всего рынка.

## 1. Факты

- По 7 профессиям сделан единый поисковый срез hh.ru в Москве (21.10.2026): 167 суммарных **совпадений поисковых запросов**, но **не** 167 уникальных профильных стажировок. Вручную рассмотрены лишь первые 14 объявлений. [Источник](research-ru-internships-2026-10-21.md).
- Дополнительно собрано **16 отдельных ссылок**, из них 14 соответствуют профессиональным направлениям, 2 — смежные. При повторном аудите **14 страниц доступны для чтения, 4 явно архивные, 1 с истёкшим дедлайном, 2 страницы не удалось открыть**. Это разные срезы — их нельзя складывать. [Таблица аудита](../data/source_audit_2026-10-23.csv).
- Независимый опрос [Changellenge BCA 2026](https://changellenge.com/tpage/bca-2026-results/) указывает на карьерный интерес к Project Manager (49%) **в разделе менеджмента**, но выборка HiPo-студентов не является репрезентативной для всех пользователей ПРОБЫ. Сравнение с IT-процентами недопустимо.
- Прогнозы [BLS 2025–2035](https://www.bls.gov/emp/tables/occupational-projections-and-characteristics.htm) относятся к США, а не к российским стажировкам. Для некоторых профессий соответствие кодов SOC неточное. **Не использовать американские открытия позиций как прямой вес российского рейтинга.**

## 2. Решение для небольшого продуктового пилота

**Проверять одновременно две гипотезы:**
1. **Менеджер проектов:** есть прямое подтверждение карьерного интереса по опросу в группе менеджмента; можно построить понятные задачи на контроль сроков, рисков и коммуникаций. Но выдача hh.ru содержит много смежных должностей.
2. **Системный аналитик:** в московских скриншотах две из двух первых карточек напрямую соответствуют роли; на открытой карточке ДИТ Москвы есть реальные рабочие задачи (требования, UML, REST API, SQL). Может повторно использовать часть образовательной базы бизнес-аналитики, но интерес студентов к отдельной роли пока не измерен.

**Кандидаты второй очереди для исследования, а не "проигравшие":**
- **Финансовый аналитик:** понятная симуляция Excel/финмодели, но открытых независимых требований пока мало.
- **Data Scientist:** подтверждены реальные ML/Python/SQL-задачи; наблюдения сильно сконцентрированы в группе Ozon, а сложность качественной автоматической проверки может быть выше.
- **Frontend/Python:** встречены конкретные технологические стажировки, но сравнивать реальный карьерный рынок по найденным примерам нельзя.
- **Интернет-маркетолог:** прикладные задачи легко моделировать, но независимого количественного измерения пользовательского спроса по этому направлению нет; найденная точная стажировка уже архивная.

**Это порядок проверки гипотез, не ранжирование по популярности.** С позиции CAPEX генерация учебных материалов с ИИ может быть недорогой; главный OPEX — предметная экспертиза, тестирование проверяющей логики, исправление ошибок, поддержка контента. Численных CAPEX/OPEX/ROI пока нельзя вычислить без реальных затрат, цены, конверсии и удержания.

## 3. Что могло бы изменить решение

| Новое свидетельство | Что оно меняет |
| --- | --- |
| Сопоставимые Wordstat-показатели по 7 профессиям за 12 полных месяцев | Проверка поискового интереса и уточнение короткого списка (но не доказательство покупательского спроса) |
| Равная экспозиция карточек 7 направлений и `waitlist_intent` | Прямой, хотя пока предварительный продуктовый сигнал |
| Очищенная база уникальных junior- и internship-вакансий с ID/URL | Достоверное сравнение доступности карьерного входа |
| Экспертная оценка и QA каждого пилотного кейса | Реальная трудоёмкость разработки и качество симуляций |
| Эксперимент с конверсией из интереса в запуск/оплату | Решение о масштабировании, возможная экономика/ROI |

## 4. Решающее правило

**Не присваивать окончательный "приоритет № 1" на основании неполных данных.** При ограниченном времени начать с двух небольших проб-демонстраций, выставить кандидатов в одинаковых условиях в каталоге и измерить интерес через события. При недостаточных данных — сообщать `недостаточно наблюдений`, а не подставлять нули.

**Уверенность:** умеренная в выборе двух направлений для пилота; низкая в точной оценке их будущей популярности и доходности.
